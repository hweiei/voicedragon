# P10–P15 · 丰富度增长路线（总方案）

> 2026-09-20 · 目标：把《声震龙楼》做厚——更多可玩性、语音×玩法深度融合、零后端社交、学习闭环反哺构筑、语音体验升级、工程加固。
> 三条输入源：① 软件工程设计思想（参数对象重构、纯规则先行、版本门控、绞杀者模式、属性测试、测试金字塔）；② 前沿端侧 AI（Silero VAD、确定性仿真复用、构建期 AI 内容管线）；③ 深度检索（见 §10 来源登记）。
> **总纪律继承 AGENTS.md 全部红线**：零后端、隐私不出设备、零素材、≤350KB gzip 本体预算、reduce-motion 降级、自动播放合规、确定性（同 seed 同局）、旧局逐位不变。

## 0. 现状盘点与缺口分析

### 0.1 已有资产（可复用的地基）

| 资产 | 现状 | 本路线的复用点 |
|---|---|---|
| 确定性引擎 | 同 (act, seed, 版本) 必同局；LCG 分离 Bot 决策流 | P12 切磋码 = 种子即链接 |
| 版本门控体系 | ruleset / buildVersion / encounterVersion / counterVersion 四层独立 | 每期新机制各挂独立版本 |
| 语音管线 | SenseVoice(sherpa-onnx WASM) + pitchy F0 + DTW 六调 + QTE 兜底 | P11 绝技、P13 辨音、P14 VAD 都走既有管线 |
| SRS/学习档案 | 90 日聚合、六调画像、错词本、档案导入导出 | P13 词林图鉴与力量化的数据源 |
| 仿真门体系 | 4 个独立平衡门 + 契约测试 + E2E 矩阵 | 每期新增门不放宽旧门 |
| 演出层 | FxDirector、粒子池、FpsGovernor、reduce-motion | P11 绝技演出复用，不新增特效系统 |
| 分享基建 | Canvas 战绩海报 + Web Share | P12 结果码复用 |

### 0.2 缺口（按"趣味杠杆"排序）

1. **角色单一**：所有人同一套牌组开局——Roguelike 可重玩性的最大杠杆（角色/构筑身份分化）完全缺失；检索印证角色与流派分化是该品类长线留存的核心（Slay the Spire 2 卖点仍是新角色；Monster Train 以"部族组合"著称）。
2. **语音玩法是单向的**：分数→出牌强度，说完即止；没有"连续说好一句长句"的高光时刻（连击/绝技缺位）。
3. **无社交回路**：单机无分享对抗；确定性引擎天然支持"种子即挑战"，是零成本的社会化杠杆。
4. **学习与构筑脱钩**：SRS 练得再好也不影响战斗——"学到的粤语变成力量"没有闭环。
5. **语音 UX 等待固定窗口**：施法要等满录音窗，节奏拖沓；无 VAD 自动断句。
6. **工程纵深不足**：确定性/编解码只有示例测试，无属性测试；无视觉回归；内容生产靠手写，扩容慢。

### 0.3 技术选型评估（采用 / 拒绝及理由）

| 候选 | 决定 | 理由 |
|---|---|---|
| Silero VAD（ONNX ~2MB，30ms 块 <1ms，MIT） | **采用（P14）** | 经既有 sherpa-onnx 运行时加载（同 WASM 栈，不引第二运行时）；模型不进首包预算，走既有模型下载/IndexedDB 基建 |
| fast-check（属性测试，MIT） | **采用（P15，dev-only）** | 确定性/编解码/存档往返/地图不变量天然是属性；devDependency 不计运行时预算 |
| Playwright 视觉回归 | **采用（P15，dev-only）** | `toHaveScreenshot` 零新依赖，防样式/布局回归 |
| WebGPU / WebGL 渲染迁移 | **拒绝** | 现有 DOM+Canvas2D 由 FpsGovernor 治理已达标；GPU 化收益低于维护与兼容成本；记录在案防反复 |
| 运行时 LLM（transformers.js v3） | **拒绝** | 0.7B+ 模型 0.7–2.1GB，与"首包轻、模型可选下载"哲学冲突；AI 能力改为**构建期内容管线**（P15），运行时零 AI |
| Tone.js / 音乐库 | **拒绝** | 违反零素材与体积红线；P11 用既有 Web Audio 合成器做纵向分层 |
| XState / ts-pattern | **拒绝** | 引依赖解决手写能覆盖的问题；预算优先留给内容 |

## 1. 总体架构思想（贯穿六期）

1. **一期一档一门**：每期独立方案文档（`docs/P1x-*.md`）+ 独立版本门控 + 独立平衡门；不共用版本号，不连带启用（沿用 P7–P9 惯例）。
2. **参数对象重构先行（P10-F1）**：`startCampaign` 位置参数已达 6 个，继续加角色参数会恶化可读性（boolean blindness/参数对象重构，Fowler）。P10 引入 `CampaignConfig` 对象为新首选 API；**旧位置签名保留为转发重载**，现有契约/E2E/组合根零改动，符合"改内核签名必须先说明理由"的纪律。
3. **纯规则先行**：每期新机制的判定全部落 `src/core/*.ts` 纯函数（预测与实际结算共用），引擎钩子只消费数据化字段（`skill.counter` 先例）。
4. **组合根完整转发**：main.ts 包装器与 `__VOICE_TOWER__` 调试口随参数对象一次收口，后续新参数只改 config 类型。
5. **复用优先于新造**：VAD 走 sherpa-onnx 既有 worker；辨音小考走既有 TTS + 问答节点基建；结果分享走既有海报管线。
6. **每期结束回填实施记录**（仓库惯例）。

## 2. P10 名伶登场 · 角色系统（最大趣味杠杆）

> 已实施完成（2026-09-20）：详见 `docs/ROSTER-PLAN.md` 与 `docs/P10-BALANCE-REPORT.md`。此处为方案级设计。

### 2.1 设计：三名粤剧行当角色

| 角色 | 行当 | 定位 | 被动「招牌」（纯函数） | 起始牌组基调 |
|---|---|---|---|---|
| **文武生** | 武场文唱 | 攻势/声势 | 「亮相」：每场战斗首次**正音**(≥85)施法 +2 声势 | 输出+增势（钉缸双×2/好犀利/执生啦/加油） |
| **花旦** | 声色艺全 | 声调/节奏 | 「绕梁」：调准分量 ≥80 时，施法额外 +2 护甲 | 多段+换手+虚弱（一齐上/快啲走/唔使惊/执生啦/有冇搞错） |
| **丑生** | 插科打诨 | 诡变/节奏 | 「打诨」：破阵拍(QTE) ≥85 时回 1 气（每回合一次） | 节奏+护甲+反击（快啲走/唔使惊/执生啦/还返俾你/有冇搞错） |

- 每角色 1 张**签名技**（进角色限定池，仅该角色的反击战役出现）：文武生「一夫当关」（重击，正音破甲）、花旦「顾盼生辉」（净化+治疗，调准加成）、丑生「搞掂晒」（伤害+转移敌方一半护甲）。
- 解锁：文武生默认；花旦 = 一幕 Boss 通关；丑生 = 图鉴收集 20 词（P13 前用成就数兜底）。解锁态存 profile（本地），标题屏诚实显示条件。
- 角色数据 `src/core/content/characters.ts`：`{ id, name, jyutping, glyph, passive, startingDeck, signature }`；被动效果按 id 分发到 `src/core/characters.ts` 纯函数（`onCastResolved / onQteResolved` 两个既有钩子点）。
- **门控**：`rosterVersion?: 1`（经 CampaignConfig）；缺失 = 旧局，起始牌组与被动逐位不变。

### 2.2 里程碑

- **F1 参数对象重构 + 角色数据层**：CampaignConfig 落地、旧签名转发、三角色数据与被动纯函数、池隔离。
- **F2 引擎钩子 + UI**：标题屏选角（含解锁态）、战斗中被动结算与日志、签名技池接入、390px 适配。
- **F3 平衡与验收**：`npm run sim:p10`（3 角色 × 3 幕 × greedy，45–65% 带、零超时；随机 Bot 下限）；契约（旧局零漂移、被动确定性、解锁持久化、JSON 往返）；E2E 三条。

### 2.3 验收门与不做

- 旧四门 + 全部门禁不放宽；本体 JS 预估 +4–6 KB gzip。
- 不做第四角色、不做角色皮肤付费化语义、不改敌人曲线来迁就角色（只调角色自有数值）。

## 3. P11 声动九霄 · 满堂彩绝技 + 纵向分层音乐 ✅ 已完成（2026-09-20）

> 实施定案与本节差异（经 `npm run sim:p11` 三轮校准，勿按旧文回退）：彩基于**裸分**（不加成）——≥85 蓄 +1、**<65 断**、其间保持；**每场绝技一次**。详见 `docs/ULTIMATE-PLAN.md` §1/§7 与 `docs/P11-BALANCE-REPORT.md`。

### 3.1 满堂彩（声韵连击 × 绝技）

- **连击槽**：连续**正音**(≥85)施法累积「彩」(0–3)；「未稳」清零（风险自选）；QTE 通道同规则（破阵拍甜区=正音）。
- **绝技（每角色一句签名长句，多音节多声调）**：彩满 3 后下一次施法前可发动，走完整语音评分（字准+调准双通道）：
  - 文武生「锣鼓响，好戏开场！」——重击 + 剩余气力保留；
  - 花旦「莺声婉转，绕梁三日」——治疗+护甲+清干扰，按调准缩放；
  - 丑生「好戏在后头」——敌方虚弱 3 回合 + 偷全部敌甲 + 换手。
- 纯规则 `src/core/bravo.ts`：`bravoTransition(prev, score)` / `ultimateResolve(character, scores)`；意图/结算共用。
- **门控**：`ultimateVersion?: 1`；绝技句进角色限定练习池（练习场可单独跟读，SRS 联动）。
- 演出：复用汉字粒子与 hit-stop（FxDirector 既有计划），reduce-motion 降级为静态高亮 + 日志。

### 3.2 纵向分层音乐（Vertical Layering）

- 既有宫调五声合成器扩为**三层**：基线层（常驻）/ 节奏层（Boss 二阶段或生命 <40%）/ 彩层（彩 ≥2）；层间用既有 lookahead 调度做 1–2 小节渐入渐出，stinger 在绝技/三★结算。
- 零素材：全部振荡器合成；`reduce-motion` 不影响音频，音量跟随既有 sound/music 开关。

### 3.3 里程碑与验收

- F1 纯规则+引擎；F2 UI/演出/音频分层；F3 平衡（绝技威力经 `sim:p11` 校准回 45–65% 带）+ 契约（彩转移确定性、绝技句练习池隔离、旧局零漂移）+ E2E（无声通道绝技全流程）。

## 4. P12 切磋码 · 零后端异步对战 ✅ 已完成（2026-09-20）

> 实施定案与本节差异（经契约与 E2E 校准，勿按旧文回退）：码为 `VT1.<base64url(紧凑JSON)>.<校验>`；
> 模式含 campaign/endless/daily/classic 四种；词缀校验走**内容世代重算**（不符即 `mismatch` 拒绝）；
> 自适应难度**随码携带**（`ab` 百分点整数）而非钉 0——同码同难需要难度也来自码。详见
> `docs/P12-CHALLENGE-PLAN.md` §1/§8 与 `docs/P12-BALANCE-REPORT.md`。
>
> 检索印证：确定性仿真 + 种子入 URL = 无服务器挑战链接与每日挑战（solodevstack 模式）；种子即链接、链接即赛局。

### 4.1 设计

- **挑战码**：`{v, act, seed, ruleset, build, encounter, counter, roster, ultimate, character, mutators}` → 紧凑 JSON → base64url（~120 字符）。入口：结算屏「发起切磋」复制码/链接（`#c=…` URL 片段，PWA 安全）；标题屏检测片段进入挑战局。
- **对局契约**：同码 + 同内容版本 = 同地图同敌人同卡池；码内含版本束，引擎版本不匹配时标题屏**明确警告并拒绝**（不静默降级）。
- **战果分享行**（spoiler-free，wordle 风格）：`声震龙楼 · 二幕 12 层 ⭐⭐⭐ 声韵均值 84 🐉`——复用既有 Canvas 海报 + Web Share。
- **本地战绩簿**：按码哈希记个人最佳（诚实声明：无排行榜，凭码自证；不连任何服务）。
- 纯规则 `src/core/challenge.ts`：`encodeChallenge/decodeChallenge`；fast-check 属性：编码∘解码=恒等、长度上限、非法输入零副作用（P15 提前埋点，P12 先示例测试）。
- 每日挑战升级：日期种子挑战自动获得分享码（dhanjit/games 的 daily-seed 模式）。

### 4.2 里程碑与验收

- F1 编解码纯函数+版本束校验；F2 入口/标题检测/战绩簿/分享行；F3 E2E（发码→另开页进同局、版本不匹配警告、旧链接不崩）+ 契约（确定性：同码两开逐位一致）。
- 不做：在线排行榜、云端存档、房间对战（违背零后端）。

## 5. P13 词林拾遗 · 词库图鉴 × 辨音小考 × 语言力量化 ✅ 已完成（2026-09-20）

> 实施定案与本节差异（经四轮仿真校准，勿按旧文回退）：轻量化原案「掌握 → +1/+2 威力」**被证伪**
> （全掌握行 92–100%、花旦一幕 76.7%），定案改为**判定保底**——练透（tier ≥1）的句子档位判定不低于 65（清晰），
> 保底值严格低于正音线 85，裸分/彩/统计全不变；tier2 的回报走非强度出口（词林点数/称号/主题）。
> 题池三态（legacy 18 / p7+粤语音色 48 / p7 无音色 18 并如实报告跳过）。
> 详见 `docs/P13-WORDBOOK-PLAN.md` §3/§8 与 `docs/P13-BALANCE-REPORT.md`。
>
> 检索印证：CAPT（计算机辅助发音训练）研究（TipTopTalk!、挑战赛制论文、FineTune/HVPT）验证三件事——最小对立对 (minimal pairs) 的「听辨→产出」循环有效、即时反馈与挑战赛制显著提升练习量与发音改善、感知训练是产出训练的有效前导。当前游戏只有产出通道，缺感知通道。

### 5.1 词林图鉴（收集养成）

- 图鉴新页签：所有技能短句/事件词/绝技句自动收录（粤拼、六调、lesson、掌握度——数据源为既有 SRS 六调画像与词汇得分）。
- 收集里程碑 → **图鉴点数**：解锁称号（纯装饰）与练习场主题（复用既有主题系统）。**不出售强度**：图鉴奖励不含战斗数值（力量化单独门控，见下）。

### 5.2 辨音小考（感知通道，minimal pairs）

- 练习场新 tab：既有 TTS 播一个词，从 2–4 个最小对立候选中选（声调对立：诗/史/试/市；声母对立：三/心；韵母对立：冬/东……词表优先取自已收录技能短语，保证学以致用）。
- 听辨错误 → 自动进 SRS 产出队列（感知→产出闭环，研究推荐范式）。
- 问答节点题池扩展：新增 30 题「听音辨字」题型（复用既有 quiz 基建，需 TTS 可用性探测，不可用时跳过该题型——诚实降级）。

### 5.3 语言力量化（学习×构筑闭环，严格门控）

- `masteryPowerVersion?: 1`：技能短语全部音节掌握度 ≥80 → 该技能 +1 威力（上限 +2）；UI 在卡面显示「已入词林 +1」。
- 数值影响必须经 `sim:p13` 校准（掌握度注入仿真档案），验收带不放宽；旧局/未开启版本零变化。
- 隐私不变：掌握度全部来自本地 SRS，不上传、不进分享码。

### 5.4 里程碑

F1 图鉴数据层+页面；F2 辨音小考+题池扩展+SRS 闭环；F3 力量化门控+平衡+契约（奖励不含战斗数值、力量化带内、旧局零漂移）。

## 6. P14 声之细织 · Silero VAD 自动断句 + 自适应难度 2.0 ✅ 已完成（2026-09-20）

> 实施定案与本节差异（勿按旧文回退）：sherpa 的 vad-asr 运行时**已含** Silero VAD 且已在跑，P14 **不新增模型下载**
> （原案「增挂 ~2MB ONNX」取消）；端点策略抽到纯函数 `src/core/endpoint.ts`（32ms 窗 / 400ms 开口 / 300ms 收口），
> 关闭开关时 worker **根本不构造策略**（关闭即逐位等价旧行为）；兜底窗口实测 8 秒（`VOICE_CAPTURE_MAX_MS=8000`，非 6 秒）。
> 难度侧定案：按 经典/无尽/幕1..3 分开记账的 Elo 式在线评级（±15% 钳制），建局时按上下文采样、续行换幕重采样；
> 每日/切磋仍钉 0 / 取码内值（P12 同码同难契约不动）。详见 `docs/P14-REFINE-PLAN.md` §1/§5 与 `docs/P14-LATENCY-REPORT.md`。
>
> 检索印证：

- 既有 sensevoice worker 增挂 **silero-vad 模型**（~2MB ONNX，30ms 块 <1ms，MIT；sherpa-onnx 原生支持，不引第二运行时），模型经既有 model-store 下载与 IndexedDB 缓存，**不进首包预算**。
- 行为：检测到语音 ≥400ms 开始 → 静默 ≥300ms 即自动截断送识别（替换固定 6s 窗口等待）；设置页开关「自动收音」，默认开；失败/未下载模型时回退现行为（降级矩阵不变）。
- 验收：施法环回时延 p50 可测量下降（E2E 计时对比），QTE 通道零影响。

### 6.2 自适应难度 2.0（本地在线启发式，不称 ML）

- 现状：`adaptiveStreak`(-2..3) 连胜连败计——粒度粗。升级为**按幕难度评分**：本地维护玩家各幕 rating，胜负后按 logistic 在线更新（K 常数调参），换算 ±15% 内的敌人数值缩放；仅经典/无尽生效（每日与切磋码局禁用，保证同码同难）。
- 纯规则 `src/core/difficulty.ts` + 契约测试（更新公式确定性、边界钳制、切磋局禁用）。
- 诚实边界：这是启发式不是机器学习；文案不夸大。
