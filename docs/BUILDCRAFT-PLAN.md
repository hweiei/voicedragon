# P8-A · 构筑成型详细方案

> 2026-09-19 · 用户授权：先出详细方案，再按「流派标签 → 删牌与升级 → 协同提示」实施。
> 状态：✅ 已按顺序实施并通过验收；下文保留实施前设计，末尾记录实测结果。不新增第四幕、敌人、Boss 或特效。

## 1. 要解决的问题

P7 有 36 技能、26 事件、8 道具，但玩家缺少整理牌组与长期投入单张卡的手段。
本期把「拿到什么」推进到「留下什么、强化什么、为什么拿下一张」。不把标签包装成新职业，不增加在线 AI 服务。

现状核查（codegraph + 定点读码）：
- `player.deck: string[]` 允许同名多张；`HandCard` 已携带真实牌组下标 `index`，但 UI/施法只传 skillId。
- 出牌在现有规则下不会弃掉该牌，本回合可以重复使用，只受声气限制。本期保留此规则，不暗改成弃牌制。
- `lookupSkill` 同时服务战斗、学习、图鉴；不能就地修改返回对象，否则升级会污染全局。
- `main.ts` 包装 `startCampaign`，新增参数必须完整转发，P7 曾在此丢参。
- 基础版及 P7 仿真、存档必须保留，不能靠修改旧测试放行。

## 2. 玩家功能与操作顺序

### A1 流派标签和构筑页

每张卡以实际机制标记「输出 / 多段 / 增势 / 护甲 / 净化 / 换手 / 治疗 / 虚弱」；一张卡可有多个能力标签。
三条构筑方向只是解释，不限制拿牌：

| 方向 | 核心组合 | 边界 |
|---|---|---|
| 连击增势 | strength + multi | 声势逐段增加伤害；显示是否缺多段或缺增势 |
| 守势攻防 | guard / hybrid / weaken | 本期不新增反击或护甲转伤，避免用「反击」文案夸大已有机制 |
| 调息周转 | cleanse / tempo / heal | 提供净化、换手、续航；不承诺免费出牌或无限循环 |

行囊新增「查看构筑」，展示：每一张牌（同名牌独立编号）、升级状态、声气费用分布、标签统计、三方向说明。
没有升级/删牌权限时仍可只读浏览。用静态文字/徽标，不引入动效。色彩之外必须有文字区分。

### A2 夜市删牌

- 仅开启构筑功能的新战役可用，每次夜市最多一次。
- 价格 = `min(75, 25 + 10 × 本局已删牌次数)` 两；不叠夜市遗物折扣，界面明确显示服务价。
- 最少保留 **5 张牌**，且不能删掉最后一张有直接伤害能力的牌。
- 选择具体牌组下标 → 二次确认（名称、编号、价格、剩余数量）→ 原子扣款/删除。
- 取消零成本；余额不足、已服务、下标/期望 id 不一致、错误阶段等拒绝时不改牌组、不扣钱、不消费 RNG。
- 已升级牌允许删除，但会明确提示升级成果一并移除；本局价格次数跨幕保持。

### A3 歇脚处升级

与回血、练声、强健体魄互斥，升级完成即离开该歇脚节点。不另外收钱，也不能同一节点再回血。
先做 **12 张代表卡**，每个实体最多一次，单路径、费用不变、语句/粤拼不变：

| 技能 | 原基础威力 → 升级 | 说明 |
|---|---:|---|
| 顶硬上 | 8 → 10 | 保留正音护甲 |
| 唔使惊 | 9 → 12 | 保留清晰护甲加成 |
| 好犀利 | 10 → 12 | 纯输出 |
| 一齐上 | 4 → 5 / 段 | 仍为 3 段 |
| 加油 | 2 → 3 | 仍受声韵与雷鼓规则影响 |
| 执生啦 | 6 → 7 | 伤害与护甲同增 |
| 稳住先 | 8 → 10 | 保留净化 |
| 接住嚟 | 4 → 5 / 段 | 仍为 3 段、2 气 |
| 唔好咁急 | 6 → 8 | 虚弱仍为 2 回合 |
| 换个角度 | 8 → 10 | 保留整手重抽 |
| 唔好放弃 | 13 → 16 | 额外 5 护甲不变 |
| 有攻有守 | 11 → 13 | 伤害与护甲同增 |

预览显示具体这张卡的原效果与升级效果。升满/未开放升级的卡给原因，不伪装成可选。
卡名以 `＋` 标识升级，学习记录仍按原 skillId 归档，不能生成重复词条。

### A4 可解释的协同提示

奖励三选一与夜市技能报价旁最多两条提示，直接来自当前牌组，纯函数可测试。
规则优先级：互补（增势↔多段）→ 功能缺口（净化/治疗/护甲）→ 换手与大牌组 → 重复/费用提醒。
例：「已有 2 张多段招式，声势会对每一击生效」「牌组尚无净化」「已有 2 张同名牌，留意抽牌占比」。
不得虚构已拥有卡、把升级副本算作新词汇、宣称必胜或给无依据的百分制 AI 推荐分。
不改变奖励随机与内容权重，不替玩家自动选牌。

## 3. 数据设计与兼容决策

### 内容版本与构筑版本分离

保留 `ruleset: "p7"` 内容池，不额外复制一套 36 张卡。新增可选 `GameState.buildVersion?: 1`，表示本局允许构筑操作。
UI 新战役显式传入版本 1；旧 P7 局/经典塔/每日/无尽没有该字段，继续原玩法。
这也保留原 P7 日榜公平性。本期只为新战役开启构筑，其他模式暂不推广。
`startCampaign(act, seed, ruleset, buildVersion?)` 仅新增尾部可选参数；跨幕续行保留该字段。

### 单张卡身份

不把 `deck` 从 string[] 改成对象数组，也不把 skillId 改成带 + 后缀的 ID。
新增 `PlayerState.upgradedSlots?: number[]`，记录升级的**牌组下标**；`removedCards?: number` 记录收费次数。
理由：现有手牌已经用该下标索引实体；战斗中只追加卡牌而不删排，管理操作仅发生在非战斗节点。
删除槽 i 时，升级槽中 i 被移除、所有 >i 的槽减一；追加卡牌不改变已有槽。
不支持排序写回牌组。将来若引入战斗移牌/重排，应升级为稳定 uid，这不在本期偷偷引入。

施法新增可选 deckIndex；开启构筑的战役必须核验「手牌中 index 与 id 匹配」再取该槽的有效卡。
UI 卡牌按钮、语音弹层、QTE、Bot 都转发 index。旧局不强制索引，原调用行为不变。
升级只返回 Skill 的新副本；保留原 id，让特定遗物/招式钩子、SRS、图鉴继续正确工作。
异步语音结算还要检查原战斗引用，防止旧弹层把技能结算到另一场战斗。

## 4. 模块与实施顺序

1. `core/buildcraft.ts`：标签表、三流派说明、升级定义/有效卡、牌组概览、删牌约束、协同提示（纯函数）。
2. `ui/buildcraft.ts`：静态模板（标签、构筑列表、升级/删牌确认预览）。
3. `core/engine.ts`：可选版本/进度字段、实体施法、删牌与升级事务；操作成功走既有 emit/save。
4. `ui/ui.ts`：行囊入口、夜市/歇脚处入口、按钮事件、异步语音/QTE 卡槽传递、奖励提示。
5. `main.ts`：包装器转发全部参数；debug hook 同步签名。
6. `core/sim.ts`：P8 专属模式让 Bot 实际升级/删牌并按有效卡出牌，原有模式策略保持。

顺序按用户要求：先写纯函数标签与展示基础，再写管理事务和升级，最后接协同提示。
没有运行时依赖、新素材、网络调用或游戏 RNG 用于提示。

## 5. 平衡与验收

- 基础版/P7 原测试不改，所有历史平衡门继续通过。
- P8 单独每幕 300 局参考 Bot，目标胜率 45–65%、零超时；升级与删牌需要真实被调用，不能只模拟旧玩法。
- 起始难度沿用 P7；若升级使胜率超线，只改 P8 专属难度表/新升级参数，记录理由与结果。
- 单测：36 卡标签完整、12 定义合法、全局对象不变、重复卡独立、删牌槽位平移、全部非法操作零副作用、成功操作零 RNG、保存/跨幕保持。
- 协同测试：多段与增势双向、缺口/重复/费用、提示最多两条、重复调用不改状态。
- E2E：新战役标记、构筑列表、取消不消费、夜市删牌/防双击、升级预览→歇脚结束、刷新恢复、升级实体通过 QTE 实际结算、旧 P7 局无操作入口。
- 性能：首包 JS ≤350 KB gzip，零新增运行时依赖；390px 移动端检查、键盘可操作按钮、reduce-motion 下信息完整。
- 每批改动后 codegraph sync；最终 `npm run ci`、Playwright、独立仿真、文档结果与提交一致。

## 6. 明确不做

本期不新增职业锁、护甲转伤、反击钩子、删牌事件、技能分支树、敌方阶段机制、第四幕、特效。
「守势反击」暂改为准确的「守势攻防」。新增反击机制若需要，另立后续方案和独立平衡门。
本期的价值是让已有卡池可整理、可投资、可理解，不宣称三种全新战斗系统已落地。


## 7. 实施结果与复现（2026-09-19）

### 完成项

- 标签与构筑页：36 张基础/扩展技能均能解释实际能力；重复卡独立编号，声气费用分布与三方向说明已展示。
- 夜市删牌：二次确认、25→35→…→75 两封顶、每店一次、至少五张与最后输出保护；可删除已升级卡，升级槽位随之正确平移。
- 歇脚升级：12 定义落地，实际数值覆盖多段/增势/护甲/治疗等机制；升级后立刻结束歇脚，与回血互斥。
- 战斗链路：实体槽位贯穿卡面 → 语音/QTE → 引擎；同名升级副本与普通副本分别按各自数值结算。异步弹层增加战斗引用校验。
- 协同提示：奖励与夜市最多两条，来自当前牌组事实；不改奖励随机或权重。
- 版本：新战役为 `ruleset=p7 + buildVersion=1`；旧 P7、经典、每日、无尽保留原行为。跨幕/JSON 存档保留升级与收费计数。
- 组合根包装器及调试入口同步新增参数；没有增加第四幕、反击机制或动效。

### P8 专属仿真

三幕各 300 局参考 Bot（语音均值 74），胜率 **49.7% / 51.7% / 56.0%**，零超时。
对应升级次数 **141 / 172 / 123**，删牌次数 **516 / 503 / 462**，证明新操作确实进入仿真。
P8 难度目标表保留独立调参入口，当前 **8 / 6.5 / 4.4**，与 P7 数值相同；本次没有下调旧版难度。

首次试跑的策略无脑升级并按基础威力删牌，会挤掉永久声韵、误删增势等辅助牌，第一/二幕胜率低于门槛。
修正的是 Bot 策略而非放宽门槛：低血优先回血；声韵至少 6 且高血时升级；夜市有余钱且牌组≥9时只精简未升级重复牌。
随机 Bot 不主动管理构筑，作为下限对照，不冒充另一种成熟构筑策略。完整报告见 `P8-BALANCE-REPORT.md`。

### 玩家体验路径

1. 标题 → **新开战役**，而不是继续旧 P7 存档。
2. 行囊 → **查看构筑**，阅读费用分布、能力标签与重复卡编号。
3. 歇脚处 → **选择升级** → 预览 → 确认；升级成果仅属于所选编号。
4. 夜市 → **选择删牌** → 二次确认；取消不消费，成功后该店按钮禁用。
5. 战斗奖励与夜市技能旁阅读「联动／补位／留意」，自由决定拿牌或跳过。

仍需真人体验校准：删牌服务的经济压力、升级与练声的机会成本、长牌组浏览体验。Bot 和自动化测试不能替代真人平衡判断。
