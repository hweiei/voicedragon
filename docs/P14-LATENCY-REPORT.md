# P14 声之细织 · 端点时延报表（策略级）

> 确定性种子基 0x20260920（与仿真同基，独立于引擎 LCG）；48 条合成轨迹；`tests/sim/p14-latency.test.ts` 复现。
> 收集窗口常量：`ENDPOINT_WINDOW_MS = 32`（sherpa silero 512 @ 16kHz）。

## ⚠ 先读这一句：这张表量的是什么

**这是策略级时延**——「最后一帧人声 → 端点判定」的毫秒数，**不含**识别、设备采样与浏览器调度开销。
CI 没有麦克风、Silero 模型 238MB 也不进 CI，所以**真机端到端时延必须在设备上量**（`DEVICE-TEST-MATRIX.md` 有手工记录位）。
本表的任何数字都不能当端到端数字引用。

## 对照口径

| 路径 | 收口条件 | 收口时延 |
|---|---|---|
| **自动收音（P14）** | 句尾静默 ≥ 300ms（`MIN_SILENCE_MS`） | 300–332ms（静默常数 + 一窗量化） |
| 旧行为（固定窗口） | 手动松手，或 `VOICE_CAPTURE_MAX_MS = 8000` 兜底 | `8000 − 说话结束时刻`：说得越早停，白等越久 |

## 结果（n = 48，说话 0.4–3.0s，长短静默混合）

| 指标 | 自动收音 | 旧行为（8 秒兜底） | 变化 |
|---|---|---|---|
| p50 | **320 ms** | 6336 ms | −95%（约 20×） |
| p90 | **320 ms** | 7296 ms | −96% |

- 自动收音的时延与说话长短**无关**（恒为静默常数 + 一窗量化）：这就是「早停不再白等」的全部含义；
- 旧行为的时延与说话长短**成反比**（短句等得最久）——断言把这条相关性也钉住了；
- 两种路径都是确定性的：同轨迹两次运行逐位一致（无隐藏时钟、无随机）。

## 机制为什么能成立

1. 端点判定抽到 `src/core/endpoint.ts`（纯函数，零 IO/零时钟依赖），worker 只把每窗 VAD 结果喂进来、按事件 flush；
2. `autoCapture=false` 时**根本不构造策略、也不喂**（不是策略内部装死）——所以关闭即等价旧行为，逐位一致；
3. 8 秒兜底保留：策略失效（异常/未下载模型/VAD 不可用）也不会挂死收音，退化路径与旧版完全相同。

## 诚实边界

- **真人反应时间未计入任何一侧**：真人松手通常比 300ms 更慢，所以旧行为的真实体验差距比上表更有可能是「更大」；
- 识别耗时（SenseVoice 端侧）不在本表内，它与两种收口方式无关（同一段音频同一模型）；
- 设备矩阵必测项：iOS Safari / Android Chrome / 桌面 Chrome 上的人工「说→停→判定」体感与误截断率（静默阈值 300ms 在嘈杂环境可能偏短，属真机调参范围）。
